## 日期口径

日历是艺术事件的年度时间表。表内“当前展示日期”保留原始内容；部分主办方公布的总展期包含邀请制预展，并不表示全部日期均向公众开放。已核实的预展差异逐项记在下表；未读取到官方细分信息时明确保留空缺，不推断公众日期、票价或开放时间。

主办方页面可能滚动更新至下一年度。核验记录是上述日期的证据快照，不是永久有效的入场承诺。历史新闻稿和年度 PDF 优先作为留档来源，下一年度应重新核验。

## 年度更新方式

1. 入口保持 `活动 → 全球艺术日历`，更新现有年度数据，不另建一级入口。此页面采用年度人工编辑，不承诺自动抓取或自动刷新。
2. 编辑 `miniprogram/packageEvents/data/calendar.ts` 中的 `CALENDAR_YEAR` 与 `CALENDAR_MONTHS`。年份常量控制页面标题、分享标题及页脚；事件 ID、英文名称、日期字符串中的年份仍需逐项同步，不能仅替换常量便声称完成年度更新。
3. 每条事件重新访问当届主办方或政府官方公告，记录来源 URL、核验日期、总展期和已公布的公众 / 预展口径。优先留存明确年份的官方新闻稿或 PDF；同一主办方有改期公告时，以后发布的适用公告为准并保留改期依据。
4. 仅收录已经确认的当年日期。不沿用上一年日期，不推算星期，不加入“日期待定”。若新年度某条尚无官方确认，不将旧日期直接迁移至新年度。
5. 每条事件归入开始月份；跨月或长展期仅保留一个主节点，完整结束日期写在日期字段。当前月内排序读取日期字符串开头的日数，因此保留以阿拉伯数字起始的日期格式；若后续引入其他格式，应先改用明确的 `startDate` 字段排序。
6. 保持 JAN–DEC 十二个月份锚点，检查月份跳转、长日期换行、重点事件层级以及末月内容可达性。核对事件 ID 唯一，名称、城市、时间与简介对应，更新本文件的完整来源表。
7. 变更构建通过后，在微信开发者工具核查实际页面。官方排期确认、代码验证、模拟器验证、真机体验及发布状态分别记录，互不替代。
